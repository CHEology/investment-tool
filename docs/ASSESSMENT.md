# 方案评估与执行顺序

方案可行。Qlib 适合承担特征工程、模型训练和研究实验；长期投资判断需要另外补齐基本面证据。第一阶段采用用户确认的顺序：先美股，再 A 股。

## 对原方案的批评

1. **把研究框架到日常产品的距离估计得太短。** 原型可以很小，可靠的数据更新、历史股票池、交易日对齐、停牌处理、通知去重和维护仍需要工程工作。第一版先完成能验证的数值闭环。
2. **20 日预测不是官方默认配置。** [Alpha158 默认标签](https://github.com/microsoft/qlib/blob/v0.9.8/qlib/contrib/data/handler.py)是两个相邻未来交易日收盘价之比。当前改为次日收盘入场、20 个交易日后收盘退出；训练和验证边界按标签终点隔离。
3. **回测最缺的是历史股票池，而不是更复杂的模型。** 用今天的指数成分回看历史会排除退市、被调出的股票，并放大存活赢家的权重。当前静态样本只能检验流程。扩大样本时，应先解决历史成员、退市回报和上市时间。
4. **官方回测收益不能作为本项目的收益目标。** 市场、股票池、持有期、成本和基准都不同。模型必须同时与相同股票池的等权组合、简单动量以及 SPY 比较，观察扣费后是否仍有增益。
5. **财报期末不是信息可用时间。** 基本面特征必须使用真实披露日期并处理更正、重述和财年差异。第一版不把当前可见的财务数据回填到历史训练中。
6. **GPT 不能凭模型排名解释因果。** 排名上升不自动意味着盈利改善或估值便宜。AI 解读应基于具体公告、报表和新闻，分别列出事实、解释与反证；评分和约束由数值流程决定。
7. **发布版本和安装版本不同。** [官方 0.9.8 发布说明](https://github.com/microsoft/qlib/releases/tag/v0.9.8)明确要求单独核对 PyPI。核查时 [PyPI](https://pypi.org/project/pyqlib/)仍为 0.9.7，因此固定官方提交 `54355232463878d2eebb91fe0ee5fa7fa1f5976c`。其安全更新涉及可执行产物和自定义配置的信任要求；本项目保存 LightGBM 文本模型，不加载远程 pickle。

## 改进后的分工

| 部分 | 负责内容 |
| --- | --- |
| 行情与证据 | 价格、复权方式、交易日、原始响应和获取时间 |
| Qlib + LightGBM | 20 日相对排序、滚动实验、可复现模型 |
| 组合研究 | 成本、调仓节奏、目标仓位、基准比较 |
| 基本面复核 | 财报、估值假设、行业变化、反证 |
| 日常观察 | 候选变化、持仓异常、需要人工查看的事项 |
| 人工判断 | 是否买卖、金额和长期投资理由 |

两年训练、半年验证、季度更新模型、20 日持有作为初始研究设定。它们尚未通过独立实验选优；调参时保留最终测试段，并记录尝试次数，避免反复查看测试集后挑选最好的结果。

## 执行进度

第一步已经落地：旧应用整体替换，美股价格到 Qlib 模型、滚动回测、候选名单和本地观察记录可运行。真实行情试跑覆盖 12 只股票与 SPY；该样本用于工程验证。

后续按以下顺序推进：

1. 获取可核对的美股历史成员和退市数据。先研究覆盖条件和授权，再决定是否需要付费供应商；当前没有引入付费数据依赖。
2. 接入 SEC 财报与公告，输出可追溯的基本面复核结果；持仓以用户提供的券商导出为准。
3. 对更广股票池做按年份和市场环境划分的验证，比较成本、换手、回撤和简单策略；开展前瞻纸面跟踪。6–12 周可以发现运行问题，不能单凭短期结果确认长期超额收益。
4. 接入 GPT 和 Telegram，先让每日摘要与显著变化通知稳定运行。需要配置用户选择的 API 和接收渠道。
5. 再扩展 A 股，单独实现交易日、历史成分、涨跌停、停牌、交易单位及 T+1 等市场约束。

当前不安装新的无人值守调度。先让用户看到有效的日常研究结果，再确定运行时间和通知频率。

## 实现原则

保持一个小型 Python 应用，直接调用成熟库。检查集中在外部输入、时间切分和收益计算；配置错误明确失败。按实际需要添加功能，不提前搭建通用插件系统、多层审批或复杂状态机。
